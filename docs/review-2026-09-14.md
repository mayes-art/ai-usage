## 追加：Cursor 方案總百分比固定 100%（已修正）

實機驗證面板時發現 Cursor 主列顯示 `100% US$20.00 / US$20.00`，與 Cursor 本身的顯示不符。
以暫時的原始回應 dump（在專案外的副本上進行，未改動工作目錄）核對 `api2.cursor.sh` 回傳：

```
totalSpend 3624, includedSpend 2000, bonusSpend 1624, limit 2000,
totalPercentUsed 14.496, autoPercentUsed 0.138, apiPercentUsed 89.875
"You've used 14% of your included total usage"
"You've used 90% of your included API usage"
```

`includedSpend` 是方案內含額度而非已用金額（`2000 + 1624 = 3624`），因此
`parseCursorUsage` 原本的 `includedSpend / limit` 恆等於 100%，與實際用量無關；
`math.Min(100, …)` 也會把超額壓成 100%。兩個模型池的百分比本來就正確。

修正後 `parseCursorUsage` 一律採用 `totalPercentUsed`，金額改由百分比乘上 `limit` 換算，
並移除 100% 截斷；沒有 `totalPercentUsed` 時方案總量視為未知，僅有分項時仍可顯示分項。
`internal/source/cursor/cursor.go` 的 `IncludedSpend` 欄位一併移除。

新增測試：`allowance fields are not usage`、`overage is not clamped`、額度欄位無百分比必須報錯、
實機形狀（`includedSpend == limit == 2000` 且 `totalPercentUsed` 14.496）必須得到 14.496% 與 US$2.90，
以及 `groups_test.go` 的 `pools without a reported total`、`live shape: low total, exhausted other`。
已確認這些測試在修正前的程式上會失敗、修正後通過。

驗證：Docker Linux（go1.27.1）`go vet ./...` 與 `go test -race ./...` 全部通過；
Windows amd64 交叉建置後實機 `report` 顯示 `Cursor IDE / CLI 14% US$2.90 / US$20.00`，
子項目 `Cursor model: 0%`、`Other model: 90%`，與 Cursor 自己的訊息一致。
`doctor` 與面板 `/api/snapshot` 亦正常回應。未驗證 macOS 與 Linux 實機。
